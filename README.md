# SeaPath ECDIS

> **Морской навигационный движок автоматизированной предварительной прокладки маршрутов с учетом батиметрии, динамического запаса под килем (PIANC DUKC), 3D State Lattice кинематики судна, векторных фарватеров и проверки безопасности IEC 61174:2015**

SeaPath — это высокопроизводительная судовая навигационная система предварительной прокладки перехода (Passage Planning) в прибрежных, стесненных и мелководных районах плавания в строгом соответствии с требованиями резолюций **IMO A.893(21)**, **IMO MSC.137(76)**, стандартов **IEC 61174:2015** и руководств **PIANC MarCom WG 121**.

Комплекс объединяет региональные матрицы батиметрии высокого разрешения (EMODnet DTM / локальные гидрографические промеры IHO S-44), физический гидродинамический бюджет динамического клиренса (DUKC), 3D State Lattice поиск по пространству состояний $(r, c, \text{dir})$, нативное C++ расчетное ядро и векторные коридоры систем разделения движения (TSS) и фарватеров.

## Ключевые возможности

### 1. Нативное расчетное C++ ядро (`seapath_native`)
- **Стандарт C++17** с Python-привязками через `pybind11`.
- **3D State Lattice A\***: расширенное пространство состояний $(r, c, \text{dir})$ с 8 дискретными направлениями движения и стартовым всенаправленным состоянием (9 состояний на ячейку). Исключает нарушение принципа оптимальности Беллмана при штрафах за изменение курса.
- **Производительность**: ускорение поиска до **67 раз** по сравнению с Python (расчет 368-мильного перехода через Черное море за **~60 мс**).
- **Zero-allocation структура**: плоские векторы состояний с инкрементальным идентификатором прогона (`run_id`), исключающим затратные `memset`/аллокации в цикле поиска.
- **Двухрежимная архитектура**: автоматическое подключение нативного C++ модуля с прозрачным фоллбэком на оптимизированный Python с полной математической идентичностью.

### 2. Гидродинамический бюджет DUKC (PIANC MarCom WG 121)
- **Скоростное проседание (Squat Effect)**: обобщенная формула Баррасса с динамическим коэффициентом стесненности акватории ($K = 100$ для открытого моря $h/T \ge 1.5$, $K = 50$ для мелководных каналов $h/T \le 1.2$ с учетом придонного подсоса, линейная интерполяция в переходной зоне).
- **Динамический крен на циркуляции (Turning Heel)**: расчет центробежного накренения $\tan\theta = \frac{V^2 (KG - d/2)}{g R GM}$ и дополнительного заглубления скулы днища $\Delta d = \frac{B}{2}\sin\theta$ с передачей фактического радиуса поворота на каждой путевой точке.
- **Волновой запас (Wave Response Allowance)**: динамическая надбавка на вертикальную качку судна ($0.35 H_s$ для укрытых вод, $0.50 H_s$ для открытого моря).
- **Приливные окна (Tidal Windows)**: гармоническая модель уровня моря для прохода лимитирующих мелководий во время приливного подъема.
- **Единый источник правды (Single Source of Truth)**: канонический бюджет глубин `compute_search_budget` синхронизирует пороги поиска A*, лучевой трассировки и аудита безопасности.
- **Границы физической применимости модели**: расчет ориентирован на водоизмещающие суда ($C_b \in [0.5, 0.9]$) в докритическом гидродинамическом режиме ($F_{nh} = V / \sqrt{gh} < 0.6$) без учета переходных волновых явлений мелководья (solitary waves) и гидродинамического взаимодействия судов при обгоне (ship-to-ship interaction).

### 3. Автоматический аудит безопасности маршрута (IEC 61174:2015)
- **Система алармов и предупреждений**:
  - `ALM-01-GROUNDING-HAZARD`: критическое нарушение изолинии безопасности (Safety Contour).
  - `ALM-02-CRITICAL-UKC`: предупреждение о маржинальном запасе под килем ($< 0.35$ м над нормативом).
  - `ALM-03-EXCESSIVE-ROT`: превышение предельной скорости изменения курса (Rate of Turn) по классам судов.
  - `ALM-04-XTD-CORRIDOR-HAZARD`: критическое обнаружение подводных отмелей и банок внутри всей 2D площади коридора безопасности XTD (`CRITICAL` аларм).
  - `ALM-05-MANEUVERING-LIMIT-VIOLATION`: критическое нарушение маневренных ограничений судна (невозможность вписать заданный радиус $R_{\min}$ из-за короткого плеча или препятствия) — блокирует маршрут (`is_safe = False`, статус `CRITICAL_HAZARD`).
  - `ALM-06-UNVERIFIED-DATA-COVERAGE`: выход коридора безопасности XTD за пределы проверенного покрытия или вход в неисследованные зоны NoData (`CRITICAL` аларм).
  - `ALM-08-RESTRICTED-ZONE-VIOLATION`: пересечение запретных или ограниченных для плавания районов (RESARE) внутри коридора безопасности XTD (`CRITICAL` аларм).
  - `ALM-09-LAND-TERRESTRIAL-HAZARD`: проникновение коридора безопасности XTD на береговую линию или топографическую сушу (`CRITICAL` аларм).
- **Сплошное 2D сканирование полосы безопасности XTD (Area Swath Scan)**: попиксельный опрос всех ячеек сетки в диапазоне $[-XTD_{\text{port}}, +XTD_{\text{stbd}}]$ вдоль каждого плеча с аналитическими эллиптическими концевыми полукружиями (endcaps) продольным радиусом $r_{\text{endcap}} = 0.5 \cdot (XTD_{\text{port}} + XTD_{\text{stbd}})$. Гарантирует обнаружение изолированных подводных опасностей в любой точке асимметричной полосы и на концевых разворотах.

### 4. Гидрографическая интеграция и векторные фарватеры
- **Консервативное слияние глубин (Shoal-bias rule)**: при объединении базовой матрицы с высокоточными промерами в судоходных водах сохраняется наименьшая (наиболее опасная) глубина, исключая искусственное завышение глубин.
- **Разделение маски суши и NoData**: топографическая суша (`land_mask`) изолирована от морских NoData ячеек (`nodata_mask`) и защищена от затирания промерами, кроме явно размеченных каналов (`dredged`/`is_canal`).
- **Защита от срезки углов (Diagonal Corner Cutting Guard)**: суперпокрытие ячеек при диагональных переходах предотвращает срезку углов мысов, банок и запретных зон.
- **Статус S-57 / ENC**: на текущем этапе коридоры TSS, рекомендованные пути и зоны RESARE импортируются через оцифрованные векторные GeoJSON-слои. Прямой бинарный парсер морских электронных карт IHO S-57 `.000` / S-101 находится в плане развития (Roadmap).

### 5. Судовая кинематика, маневрирование и экспорт
- **Круговые дуги циркуляции**: построение сопрягающих дуг поворота с плотной дискретизацией (24 точки) и проверкой глубин по всей дуге с полной алгоритмической идентичностью между C++ и Python.
- **Точки перекладки руля (Wheel Over Point, WOP)**: вычисление упреждения начала маневра с учетом времени перекладки рулевого привода (12 сек).
- **Экспорт в RTZ 1.1 XML (IEC 61174:2015 Annex S)** для коммерческих судовых ЭКНИС (Furuno, Kongsberg, Transas/Wärtsilä, JRC, Raytheon Anschütz).
- **Экспорт в GPX 1.1** для картплоттеров (OpenCPN, Garmin, Raymarine, Navionics).

## Гидродинамические формулы DUKC

### 1. Скоростное проседание судна (Squat Effect)
Проседание корпуса судна на ходу рассчитывается по формуле Баррасса:

$$\Delta h = \frac{C_b \cdot V^2}{K}$$

Где:
- $\Delta h$ — динамическое проседание (в метрах);
- $C_b$ — коэффициент общей полноты корпуса (Block Coefficient);
- $V$ — скорость относительно воды (в узлах);
- $K = 100$ при $h/T \ge 1.5$ (открытая глубокая вода);
- $K = 50$ при $h/T \le 1.2$ (стесненное мелководье, придонный подсос);
- $K = 50 + 50 \cdot \frac{h/T - 1.2}{0.3}$ при $1.2 < h/T < 1.5$ (переходный режим).

### 2. Крен и заглубление скулы на циркуляции (Turning Heel)
Центробежная сила при перекладке руля вызывает динамический крен:

$$\tan\theta = \frac{V^2 \cdot (KG - d/2)}{g \cdot R \cdot GM}$$

Дополнительное погружение скулы днища внешнего борта:

$$\Delta d_{\text{heel}} = \frac{B}{2} \cdot \sin\theta$$

Где:
- $V$ — скорость судна в м/с ($V_{\text{kts}} \cdot 0.514444$);
- $R$ — радиус циркуляции (в метрах);
- $GM$ — поперечная метацентрическая высота;
- $B$ — ширина судна (Beam).

### 3. Волновой запас (Wave Response Allowance)
Поправка на вертикальную качку (heave, pitch, roll) по руководству PIANC WG 121:

$$\Delta d_{\text{wave}} = \begin{cases} 0.35 \cdot H_s, & \text{укрытые воды / подходной канал} \\ 0.50 \cdot H_s, & \text{открытая прибрежная акватория} \end{cases}$$

### 4. Итоговая динамическая осадка и безопасная глубина
Полная динамическая осадка:

$$T_{\text{dynamic}} = T_{\text{static}} + \Delta h_{\text{squat}} + \Delta d_{\text{heel}} + \Delta d_{\text{wave}}$$

Минимальная безопасная глубина по навигационной карте:

$$D_{\text{chart}}^{\text{min}} = T_{\text{dynamic}} + \max(0.05, \delta_{\text{UKC}} - \Delta h_{\text{tide}})$$

## 3D State Lattice A* и функция стоимости

В 3D State Lattice узлом пространства поиска является тройка $(r, c, \text{dir})$, где $\text{dir} \in \{0..7\}$ — дискретный вектор входящего курса, а $\text{dir}=8$ — стартовое состояние. Это обеспечивает строгое выполнение принципа оптимальности Беллмана при расчете штрафов за перекладку руля.

$$\text{Cost} = \left( C_0 \cdot \left( 1.0 + \frac{8.0}{\max(0.05, D - D_{\text{chart}}^{\text{min}})} \right) \cdot W_{\text{fairway}} \right) + P_{\text{heading}}$$

Где:
- $C_0$ — базовая евклидова длина шага ($1.0$ для кардинальных направлений, $\sqrt{2}$ для диагоналей);
- $W_{\text{fairway}}$ — весовой коэффициент ($0.30..0.35$ в фарватере/TSS, $1.0$ в свободных водах, $\ge 500$ в запретных зонах RESARE);
- $P_{\text{heading}}$ — кинематический штраф за отклонение направления от предыдущего вектора движения:
  $$P_{\text{heading}} = \begin{cases} 0.35 \cdot (1 - \cos\theta), & \cos\theta \ge 0 \\ 1.8 + 1.2 \cdot (-\cos\theta), & \cos\theta < 0 \end{cases}$$

## Установка и запуск

### Требования
- Python 3.10+ (64-bit)
- Компилятор C++17 (MSVC на Windows или GCC/Clang на Linux)
- Зависимости `rasterio`, `pybind11`, `fastapi`, `uvicorn`, `pydantic`

### 1. Клонирование и виртуальное окружение
```bash
git clone https://github.com/EugeneBarinov/sounder-path.git
cd sounder-path

python -m venv venv
# Windows (PowerShell):
.\venv\Scripts\Activate.ps1
# Linux / macOS:
source venv/bin/activate

pip install -r requirements.txt
```

### 2. Сборка нативного C++ модуля
```bash
python setup.py build_ext --inplace
```

### 3. Запуск тестов и валидации
```bash
python -m pytest tests/ -v
```

### 4. Бенчмарк производительности и контроль паритета
```bash
python scripts/benchmark.py
```
*Инженерные критерии геометрического и гидрографического паритета (C++ vs Python):*
- Расхождение по дистанции: $\Delta \le 0.5$ NM (фактическое: $0.00$ NM);
- Расхождение по минимальному клиренсу: $\Delta \le 0.1$ м (фактическое: $0.0$ м);
- Расхождение по числу путевых точек: $\Delta \le 2$ WP (фактическое: $0$ WP).

*Типовой результат (Черное море, Сочи → Евпатория, 363 NM):*
- Python Reference Router: ~15 500 ms
- C++ Native Router: **~210 ms** (ускорение в **70..74 раза**)
- Паритет геометрии, фарватеров и запаса под килем: 100% подтвержден.

### 5. Запуск навигационного сервера
```bash
uvicorn backend.main:app --host 0.0.0.0 --port 8000 --reload
```
Веб-интерфейс доступен по адресу: `http://localhost:8000`.

### 6. Запуск через Docker (docker-compose)
**Боевой режим (Production Fail-Closed):**
По умолчанию контейнер собирается с переменной окружения `SEAPATH_ENV=production`. В этом режиме система строго требует наличия валидного батиметрического растра в `data/raw/E8_2024.tif`. При отсутствии боевых данных сервер завершает запуск с критической ошибкой, а встроенный healthcheck возвращает HTTP 503 (`data_status: "synthetic_demo"`), предотвращая опасную навигацию на демонстрационных глубинах.
```bash
# Боевой запуск (с монтированием data/):
docker compose up -d --build
```

**Демонстрационный режим (Demo Mode):**
Для локальной демонстрации интерфейса без скачивания регионального GeoTIFF предусмотрен отдельный профиль `demo`:
```bash
# Демонстрационный запуск на синтетической модели глубин:
docker compose --profile demo up -d seapath-ecdis-demo
```
Сервер будет доступен на `http://localhost:8001`.

## Навигационный API

### `POST /api/route`
Расчет безопасного маршрута с учетом батиметрии, кинематики, фарватеров и гидродинамики DUKC.

**Пример запроса:**
```json
{
  "waypoints": [
    {"lon": 33.36, "lat": 45.18},
    {"lon": 33.50, "lat": 44.62}
  ],
  "draft": 2.5,
  "speed_knots": 12.0,
  "ukc": 0.6,
  "turning_radius_m": 200.0,
  "fairway_preference": 1.0,
  "tide_offset_m": 0.2,
  "wave_height_m": 0.5,
  "block_coefficient": 0.65,
  "port_xtd_m": 185.2,
  "stbd_xtd_m": 185.2
}
```

**Ответ включает:**
- `route`: GeoJSON LineString сглаженной траектории перехода с циркуляциями;
- `corridor`: GeoJSON Polygon зоны безопасности XTD;
- `turn_arcs`: GeoJSON FeatureCollection дуг поворота и маркеров WOP;
- `waypoints`: структурированная таблица плана перехода (дистанции, истинные курсы, ROT, WOP, клиренс);
- `profile`: непрерывный профиль глубин и запаса под килем;
- `safety_audit`: статус проверки по IEC 61174, перечень алармов (`ALM-01`..`ALM-05`);
- `dukc_budget`: детальная расшифровка составляющих динамической осадки;
- `bottlenecks`: анализ лимитирующих участков и рекомендации по безопасной скорости.

### `POST /api/export/rtz`
Экспорт рассчитанного плана перехода в формат **RTZ 1.1 XML (IEC 61174:2015 Annex S)** для загрузки в судовые ЭКНИС.

### `POST /api/export/gpx`
Экспорт плана перехода в стандартный формат **GPX 1.1** для картплоттеров.
